# A+ 图片像素硬性规则 · 2026-10-30

用户决定：网页与 Mobile 图片都必须按适用字段 minimum 的正整数倍制作；宽、高必须使用同一个倍数，默认 2 倍。不得仅满足“不小于最低值”、独立取整宽高、使用近似宽高比或任意超大尺寸。

当前用户截图中的字段：网页 minimum 1464×600 → 默认 **2928×1200 px**；Mobile minimum 600×450 → 默认 **1200×900 px**。这是本项目生产硬性规则，不冒称 Amazon 所有模块统一要求。其他模块必须记录其实际 minimum 与证据，再按相同公式执行。非默认倍数需任务明确指定，并记录理由和 multiplier。

生成前读取 `assets/image-dimensions-policy.json` 并锁定目标字段、minimum、证据和倍数；生成后、交付计划、远端原字节回读均调用 `scripts/image-dimensions.cjs` 校验实际像素，失败则禁止将文件列为可上传最终图片。不得用清单声明代替真实 PNG 宽高。

保留硬件、Logo、文字比例和完整内容。优先按可编辑配方重排；只做既有图片像素矫正且无法无损重排时，等比缩放并扩展协调背景，记录留边与源图清晰度限制，不能拉伸或裁掉重要内容。手机仍独立设计，不从桌面宽图直接缩小冒充手机稿。满足尺寸不等于增加原始细节、风格批准或 Amazon 接收/发布。

命令：`node scripts/image-dimensions.cjs desktop <file.png>` 或 `mobile <file.png>`；明确其他整数倍时附加倍数参数。现有手机白蓝渲染器仍使用 2 倍设计坐标；其他倍数需显式重排与字号检查。

替换前归档当前连贯旧版本（图片、清单、配方及说明），保留稳定 Drive ID；更新实际图片、像素/哈希清单与当前入口。回读原字节、像素、SHA256 和实际父目录。可复用规则/scripts/assets/templates 同步 GitHub 与 Drive 版本快照。产品图片与配方只更新精确产品 Drive 目录，历史 GitHub 产品副本保留。
