## 设计边界

Mobile 是独立排版，不是桌面图等比缩成窄条。保留用户选择的白/深蓝/蓝色、真实产品主体、自然办公摄影和原有九个买家问题；按手机阅读重排，不把场景全部改成参数卡。文字可以合理换行或缩短，完整限定及解释保存在对应模块的原生正文中。原有桌面图片保留，手机当前图另放在产品 `premium/assets/mobile/`。

以下是当前白蓝商务方向的复用方法，不自动成为所有 Gaming、Mini PC、Business Laptop 的风格批准。新产品按真实形态及既有风格调整；具体预览仍由用户判断。读取当前仓库 AGENTS/WORKFLOW，并执行适用的通用原始资产/事实规则。

## 尺寸与文字层级

| 项目 | 本设计执行值 |
|---|---|
| 导出 | 1200×900，4:3，sRGB、不透明 PNG、72 dpi、每张 <2,000,000 bytes |
| 对应已观察上传框 | Mobile minimum 600×450；其他模块逐项核实，不能扩展为全站统一规格 |
| 标题 | 72–82px，通常一至两行；深蓝，关键短语可蓝色 |
| 主要数字 | 52–84px，参数与标签成组 |
| 正文/标签 | 44–48px；实际最小嵌入文字 42px |
| 限定说明 | 42–44px，必要时拆行或迁移原生文字；不能删掉 OPTIONS、Up to、不随附或单核睿频限定 |
| 最小显示检查 | 42px 在 360px 宽预览中约为 12.6px。它是内部起点，最终仍看实图，不能以脚本通过代替可读性 |
| 留白 | 左右约48px；标题/主体/脚注有清楚间距，禁止遮字、贴边、拉伸产品 |

字号不足时先重排、合理精简或使用模块原生文字，不能自动降字号绕过检查。型号可用正常 Title Case，避免把全屏变成重复全大写标签。

## 上传信息与披露

每张图片必须有准确描述的 Alt text，本包控制在1–100字符。保留型号、处理器、容量选项、道具/软件边界；不要塞关键词或把正文所有参数都塞进 Alt。

02/08/09 含写实 AI 手部；PNG 内嵌 XMP `dc:subject / rdf:Bag / rdf:li = contains-synthetic-performer`，检查最终上传原文件，不能只在文件名写 AI。A+ Creative Assets 上传时也可使用 Amazon 的“AI-generated people”选项。没有人物的原产品/信息页不误标为有人物。清洗/转换/再次导出后必须复查标签是否保留。

图片内合理缩短的脚注要有语义完整的原生正文，例如“Peripherals not included”在本例明确对应显示器、键盘、鼠标；完整列表保存在逐图正文里。容量 OPTIONS、Up to、Actual performance varies 等重要口径仍直接印在相关图内。

## 验收与交付

1. 核实当前精确产品、已有事实记录、原图和风格范围，不用新设计触发无关工作簿重做。
2. 填 [简报](../templates/mobile-aplus-brief.md)、[任务结构](../templates/mobile-aplus-job.json)，实际坐标及文字写入产品 `mobile/design.json`；参考 [VD-744 完整实例](../products/VD-744/US/mobile/design.json)。空模板不能直接渲染。
3. 由通用渲染器输出手机图片和 hash-bound manifest。原生正文/Alt/AI标记/源图哈希与每图素材对应。
4. 运行结构/元数据检查，再查看每张1200px原图及360/390/400px手机预览；200px只用于识别与主信息，不承诺脚注可读。核对准确硬件、字词、容量/限定、Logo、局部修整和图片贡献。
5. 检查最终图、配方、原始素材/补丁和文字可在独立 checkout 重建；不依赖临时目录、签名链接或模型服务才能重新导出当前包。
6. 更新当前 GitHub 图片/清单/规范，Git历史保留之前完整版本；核对远端字节和源哈希。把文件检查、视觉检查、用户批准、实际后台预览、Amazon审核/发布分别记录。
7. 清理本次已交付的本地临时 checkout/缩略图/未采用候选，不删除未交付唯一副本。
